# soul/ — Hermes' personality

| File | What it is |
|---|---|
| `SOUL.md` | Ships to `$HERMES_HOME/SOUL.md`. Written *to* Hermes. Loaded into every session. |
| `DESIGN-NOTES.md` | Written *about* SOUL.md, for us. Rationale, worked examples, failure modes. Never ships. |

## Install target

```
/var/lib/hermes/SOUL.md      # $HERMES_HOME for the `hermes` user
```

Hermes Agent loads `SOUL.md` from `$HERMES_HOME` automatically when present.
It sets identity, not project rules — no other config file is needed for
personality.

## Editing rules

1. **SOUL.md is written in second person, to the agent.** Not documentation.
   If a line reads like a spec, it belongs in `DESIGN-NOTES.md`.
2. **Every rule must be observable.** "Be kind" is unfalsifiable. "Most
   answers are one to three sentences" can be checked.
3. **Keep it under ~7 KB.** It's in the context window of every single turn.
   Cost is paid per message, forever.
4. **A new rule needs a worked example** in `DESIGN-NOTES.md` §5, or it isn't
   testable and shouldn't land.
5. **Banned-phrase changes are breaking changes.** They shape every reply.

## Relationship to the safety model

The SOUL shapes *how* Hermes speaks about safety. It does not implement it.

Approval cards, refusals, and red-card warnings are rendered by `hermesctl`
from verb definitions — **not generated by the model**. A drifting or
jailbroken personality cannot soften a warning, because it never wrote one.

The SOUL controls the conversation around the card. The broker controls the
card.
