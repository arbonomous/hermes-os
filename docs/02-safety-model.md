# HermesOS — Safety Model

The safety model has four pillars: **capabilities** (what is even possible),
**approvals** (what needs a yes), **audit** (what happened), **rollback**
(how to undo). Each is described below in enough detail to implement.

---

## 1. Capabilities — the verb surface

Hermes cannot run arbitrary privileged commands. It can only invoke **verbs**.
A verb is a named, typed, versioned operation defined in `/etc/hermesos/verbs.d/`.

```yaml
# /etc/hermesos/verbs.d/pkg.install.yaml
verb: pkg.install
summary: "Install an application from Ubuntu's official software catalogue"
args:
  names:
    type: list[package_name]     # validated against ^[a-z0-9][a-z0-9+.-]*$
    max_items: 20
risk: medium
snapshot_before: true
dry_run: "apt-get install --simulate {names}"
execute:  "apt-get install -y {names}"
explain: |
  I'll install {names} from Ubuntu's official software catalogue.
  This adds new programs to your computer. It doesn't remove anything.
  I'll make a restore point first, so we can undo it.
```

Properties that make this safe:

1. **No string interpolation into a shell.** Args are validated by type, then
   passed as an `argv` array to `execve`. There is no shell, so there is no
   injection, no `;`, no backticks, no `$()`.
2. **Closed set.** If there is no verb file, the operation cannot happen. Adding
   a verb is a deliberate, reviewed, packaged act — not something the agent can
   do at runtime.
3. **Self-describing.** Every verb carries its own plain-English `explain`
   block, so the approval card is never generated by the model. The model
   *chooses* the verb; the *system* writes the warning. A hallucinating model
   cannot produce a reassuring-but-false description of a destructive act.

### Risk tiers

| Tier | Meaning | Default policy | Snapshot |
|---|---|---|---|
| `safe` | Read-only, no side effects | auto-allow | no |
| `low` | Reversible, user-scoped (write a file in $HOME) | auto-allow, logged | no |
| `medium` | System-modifying, reversible (install pkg, enable service) | **ask** | yes |
| `high` | System-modifying, hard to reverse (remove pkg, edit fstab, user mgmt) | **ask + typed confirm** | yes |
| `critical` | Destructive/irreversible (format, wipe, delete user data, firmware) | **ask + typed confirm + 5s delay + second sentence** | yes, and refuses if snapshot fails |

### The forbidden set

Some things have no verb at all in v0.1, by design:

- `dd` / `mkfs` / `wipefs` to any device that is not explicitly named by the
  user in the same turn
- Modifying `/etc/hermesos/policy.yaml` or anything in `verbs.d/`
  → **the agent can never widen its own permissions**
- Modifying `/var/log/hermesos/audit.jsonl`
- Adding a user to `sudo`, or changing the human's password
- Disabling `hermesctl`, `snapshotd`, or the audit writer
- Installing from arbitrary URLs / `curl | sh`
- Editing GRUB's default entry

These are refused by the broker with a friendly explanation and a pointer to
`!shell` if the human genuinely wants to do it themselves. **The human is never
blocked. Only the agent is.**

### Self-modification lock

`hermesctl` verifies on every invocation that `policy.yaml` and `verbs.d/`
match a signed manifest hash stored at `/usr/lib/hermesos/manifest.sha256`
(root-owned, 0444). If they don't match, the broker enters **read-only mode**:
`safe` and `low` verbs still work, everything else refuses with:

> Something changed my safety rules and I can't verify they're still the ones
> you approved. I've switched to read-only mode until you check.
> Run `hermes-repair` to review what changed.

This turns the most dangerous possible attack (agent edits its own leash) into
a loud, self-healing failure.

## 2. Approvals — the gate

### 2.1 The approval card

The single most important UI in HermesOS. Rendered by the **broker**, not the
model. Structure:

```
  ┌──────────────────────────────────────────────────────┐
  │  I'd like to install VLC                             │
  │                                                      │
  │  WHAT THIS DOES                                      │
  │    Adds the VLC video player to your computer.       │
  │                                                      │
  │  WHAT CHANGES                                        │
  │    + 4 new programs added (18 MB)                    │
  │    · Nothing is removed or overwritten               │
  │                                                      │
  │  IF YOU CHANGE YOUR MIND                             │
  │    Say "undo that" any time — I'm making a restore   │
  │    point first.                                      │
  │                                                      │
  │  [Y] Yes, go ahead    [N] No thanks    [?] Tell me   │
  │                        more                          │
  └──────────────────────────────────────────────────────┘
```

Rules for the card:
- **Four sections, always the same order.** Predictability builds trust.
- "WHAT CHANGES" comes from the **dry run**, not from the model. Real numbers.
- "IF YOU CHANGE YOUR MIND" is always present. It is the anxiety-reducer.
- `?` expands to show the literal command that will run — for the curious and
  for advanced users. Hidden by default, never more than one keystroke away.
- Default on bare Enter is **No**. Silence is never consent.

### 2.2 Escalation for `high` / `critical`

For `high`: the user must type the word shown, e.g. `remove`.
For `critical`: the card is red, includes a **plain sentence of consequence** at
the top, enforces a 5-second read delay before input is accepted, and requires
typing a full phrase:

```
  ⚠  THIS PERMANENTLY ERASES DATA

  Everything on the USB stick "Backup2019" will be deleted.
  There are 1,204 files on it (14 GB). This cannot be undone —
  a restore point will NOT bring these files back.

  If you're sure, type:  erase Backup2019
  Or press Esc to cancel.
```

Note the honesty: for genuinely irreversible acts we say *the safety net does
not apply here*. Never imply undo works when it doesn't.

### 2.3 Approval modes

| Mode | Behaviour | How set |
|---|---|---|
| `guided` (default) | Everything `medium`+ asks | shipped default |
| `trusted` | `medium` auto-approves within a session after first yes for that verb | user says "stop asking about installing things" |
| `strict` | Even `low` asks | for shared/kiosk machines |
| `paranoid` | Everything asks, `!shell` disabled | for handing the machine to a child |

`trusted` scope is **per-verb, per-session, time-boxed (default 30 min)**, and
is announced when it starts and when it expires. It never persists across
reboot. There is no global "never ask me again" — that is the one convenience
we refuse to ship.

### 2.4 Batch approval

If the agent needs three related actions, it presents **one card listing all
three**, not three cards. Approval fatigue is a real security failure mode;
users who click through 12 dialogs are not consenting, they are dismissing.
Cap: max 8 actions per card, and every action in a batch must be the same risk
tier or lower than the card's headline tier.

## 3. Audit — the notebook

### 3.1 Format

Append-only JSONL at `/var/log/hermesos/audit.jsonl`, owned `root:hermes-audit`,
mode `0640`, with `chattr +a` where the filesystem supports it. The `hermes`
user has **write-append only, no read of prior lines, no truncate**.

```json
{
  "ts": "2026-08-06T14:22:31Z",
  "seq": 1841,
  "prev_hash": "sha256:8f3c...",
  "session": "20260806_141902_a1b2",
  "actor": "hermes",
  "verb": "pkg.install",
  "args": {"names": ["vlc"]},
  "risk": "medium",
  "policy": "ask",
  "decision": "approved",
  "decided_by": "human",
  "snapshot": "hermesos-auto-2026-08-06T14:22:29Z",
  "dry_run_summary": "4 newly installed, 0 removed, 18.4 MB",
  "exit_code": 0,
  "duration_ms": 8421,
  "hash": "sha256:c19a..."
}
```

Each record hashes the previous one (`prev_hash`) — a hash chain. Tampering
with any earlier line breaks verification, detectable by
`hermesctl audit verify`. Not cryptographically signed in v0.1 (no TPM
requirement), but tamper-**evident**, which is the honest claim.

### 3.2 The human-readable mirror

`/var/log/hermesos/audit.txt` — same events, rendered as prose:

```
Thu 6 Aug, 2:22pm — You approved: install VLC.
  I made restore point "before-vlc" first. It worked (8 seconds).

Thu 6 Aug, 2:31pm — You said no to: remove old kernels.
  Nothing changed.

Thu 6 Aug, 3:04pm — I refused my own request: edit /etc/sudoers.
  That's on my forbidden list. I told you to do it yourself if you meant it.
```

Because "full audit logging" is worthless if the person it protects can't read
it. The user reaches this by saying **"what have you done today?"** — which is
a first-class, documented question, surfaced in onboarding.

### 3.3 What is never logged

Passwords, key material, and the contents of files the user marked private. The
audit records *that* a file was read and its path, never its bytes.

## 4. Rollback — the undo

### 4.1 Snapshot triggers

- Automatically before any `medium`+ verb
- Daily at first boot of the day
- Manually: "make a restore point" / `hermesctl snapshot create <name>`
- Before `hermes update` and before any kernel update

### 4.2 Restore paths, easiest to hardest

| Situation | How |
|---|---|
| "That was a mistake" | Say **"undo that"** — restores the pre-action snapshot |
| "Something broke today" | Say **"go back to this morning"** — picks the snapshot |
| "I can't log in" | Boot menu → *HermesOS (previous restore point)* |
| "Nothing boots" | Ubuntu live USB → `hermesos-rescue` script on the ISO |

`undo that` is scoped and specific: it names what it will revert and what will
be lost (anything done *since* that snapshot), and requires confirmation. It is
itself a `high` verb — undo is powerful too.

### 4.3 Retention

10 automatic + 5 daily + unlimited manual, pruned oldest-first when the
filesystem passes 80% full. The user is warned at 85% *before* pruning becomes
aggressive, in plain language, with an offer to help clear space.

### 4.4 What snapshots do NOT protect

Stated up front in onboarding and repeated in `critical` cards:
- Files on external drives / USB
- Data sent over the network
- Emails sent, messages posted
- Anything in a directory excluded from the snapshot subvolume

Honesty about the limits of the safety net is part of the safety net.

## 5. Growing capability — how HermesOS learns

A frozen verb list cannot deliver "customize your computer by talking to it".
An unrestricted agent cannot be safe. HermesOS resolves this with a third
path: **the verb set grows, one deliberate consent at a time, and never
shrinks your understanding of what your machine can do.**

### 5.1 The teaching moment

When the user asks for something no verb covers, Hermes does **not** fail and
does **not** improvise a shell command. It writes a *proposal*:

```
  ┌──────────────────────────────────────────────────────┐
  │  I don't know how to do this yet — want to teach me?  │
  │                                                      │
  │  YOU ASKED                                           │
  │    "make the fans quieter when the laptop is cool"   │
  │                                                      │
  │  WHAT I'D NEED TO LEARN                              │
  │    A new ability called "fan.set-profile" that can   │
  │    change the cooling profile. It would run:         │
  │                                                      │
  │      /usr/bin/asusctl fan-curve --set quiet          │
  │                                                      │
  │  WHAT THAT MEANS                                     │
  │    Controls how fast your fans spin. Reversible —    │
  │    you can always set it back to automatic.          │
  │    I'd class this as MEDIUM risk, so I'll still ask  │
  │    you each time before I use it.                    │
  │                                                      │
  │  IF YOU SAY YES                                      │
  │    I'll remember this permanently. You can see       │
  │    everything I've learned by saying "what can you   │
  │    do?", and remove any of it with "forget how to    │
  │    do X".                                            │
  │                                                      │
  │  [Y] Teach me   [N] No   [?] Explain the command     │
  └──────────────────────────────────────────────────────┘
```

Approved proposals are written to `/etc/hermesos/verbs.d/local/`, the manifest
is re-signed, and the ability is permanent, reusable, listable, and revocable.
**Your machine ends up with a verb set shaped like your life.** Two HermesOS
boxes six months apart will not have the same abilities — that is the point.

### 5.2 Rules that make learning safe

| Rule | Why |
|---|---|
| Proposals show the **literal command, expanded by default** | Normal cards hide it; teaching cards never do. You are granting a power — you see exactly what it is |
| Learned verbs start at **minimum `medium` risk** | Learning something never makes it auto-approve. First use still asks |
| Learned verbs are **re-checked against the forbidden set** at proposal time *and* every execution | No learned verb can ever reach sudoers, the policy files, the audit log, or the agent's own leash |
| A proposal **cannot be executed in the turn it is approved** | One beat of separation between "yes, learn that" and "yes, do that now". Two consents, not one |
| Proposals are **rate-limited** (default 3/hour) | Prevents an injected or confused model from flooding you into fatigue |
| The command must resolve to an **existing binary on disk** | No learning "download this and run it" |
| Every learned verb is tagged `origin: learned` in the audit | You can always tell shipped abilities from taught ones |

### 5.3 Reviewing what it knows

- **"What can you do?"** → grouped list: *shipped* abilities vs *things you
  taught me*, each with when it was learned and last used.
- **"Forget how to do X"** → removes the verb file, re-signs the manifest,
  logs it. Instant, no side effects.
- **Monthly nudge:** *"You taught me 4 things last month, and I haven't used 2
  of them. Want to review?"* Unused power gets pruned by default, not
  accumulated silently.

### 5.4 The honest limit

This makes the system *arbitrarily capable over time* while keeping every
increment consensual and reversible. It does **not** make it safe against a
user who approves everything without reading. Nothing can. What it guarantees
is that no capability ever appears without a card, a log line, and a way to
take it back.

## 6. Threat model (brief, honest)

**In scope, mitigated:**
- Model hallucinates a destructive command → verb allowlist + approval card
  written by the system, not the model
- Model is prompt-injected by web content or a file → same; injection can only
  ever *request* a verb, and the human sees a truthful card
- User approves something bad by accident → snapshot + undo + audit
- Agent tries to widen its own permissions → manifest hash lock, read-only mode
- Silent tampering with history → hash-chained audit

**In scope, partially mitigated:**
- Approval fatigue → batching, tiering, per-verb trust with expiry. Still a real
  risk; the mitigation is design discipline, not a technical control.
- A user who types `!shell` and runs `rm -rf /` → we cannot and should not stop
  the machine's owner. Snapshots + GRUB entry are the net.

**Out of scope for v0.1 (documented, not solved):**
- Physical attacker with disk access (no FDE by default — offered in installer)
- Malicious upstream model weights
- Compromised Ubuntu mirror
- A user who deliberately disables the broker

We write these down rather than implying the system is bulletproof. Beginners
deserve accurate mental models more than they deserve comforting ones.
